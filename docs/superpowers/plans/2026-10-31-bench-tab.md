# Bench Tab and Start Page Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A Bench tab in `scrimmage edit` that shows an idea session live on the projector (Stage layout, "Change it"
panel, 3D editing with plain-word help, run, sweep, compare, gallery), kept in step with the agent's MCP runs and edits,
plus a start page so `scrimmage edit` needs no file name.

**Architecture:** Bench-side pieces live in `scrimmage/bench/`:
- `fields.py`: help and choices.
- `problems.py`: every problem in a file, each with its dotted key.
- `session.py`: the session folder's run log, talked-about list and cross-process run lock.

The CLI and the MCP tools use all three. The editor gains:
- `assembler/bench_edits.py`: tomlkit edit ops;
- `assembler/bench_view.py`: 3D view JSON;
- `assembler/bench_session.py`: the server-side session behind `/api/bench/*`;
- start and open support in `App` (`/api/app/*`);
- three front-end modules: `start.js`, `bench.js` (the Stage) and `bench_edit.js` (3D editing).

Dotted keys (`wheel.top.diameter`, `shaft.top.target_rps`, `run.duration`; entry keys `bar.kicker`) are the one
address for a field everywhere: problems, focus, edits, sweeps (they are already the `[sweep]` and `with_overrides`
convention).

**Tech Stack:** Python 3.11+, MuJoCo, tomlkit, the editor's stdlib HTTP server and long-polls, ES-module front end with
the vendored three.js, pytest and Playwright.

**Spec:** `docs/superpowers/specs/2026-10-31-bench-tab-design.md`

## Global Constraints

- **The page stays local:** 127.0.0.1 only, every `/api/*` request needs the token header, as in `assembler/server.py`'s contract.
- **The bench file is the source of truth.** Edits keep comments and order (tomlkit through `ConfigDoc`); the
  existing format in `bench/spec.py` is unchanged.
- **Never show a result without its UNCALIBRATED line.** Never lose a hand edit or an agent edit to the other. Never
  leave the file and the screen disagreeing silently.
- **One bench run at a time on the machine,** from the page, the CLI or the MCP tools; a second waits.
- **The CLI and MCP keep working** with the same commands and arguments. `scrimmage edit FILE`, `--new` and
  `--new-scenario` behave as today.
- **Existing bench files and `examples/bench/*.toml` still load.** Overlap checks are warnings, never errors.
- **Plain words in every message and help text** (match `docs/bench.md`'s voice); units shown with every number.
- **Tests:** pytest for Python; Playwright browser tests (`pytest -m browser`), which skip without Chromium unless
  `SCRIMMAGE_REQUIRE_BROWSER=1`.
- **Commits** end with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`. Verify locally; push nothing.

## Review Focus

1. **An agent edit while someone is typing on the page.** The other edit must never be lost silently. The page reloads
   the idea and says "the agent changed this idea; your edit to <field> wasn't saved". Test: Task 6
   `test_outside_edit_during_page_edit_is_refused_and_reported`.
2. **A bench file that isn't valid TOML, or is half-written by the agent at the moment the server reads it.** It is
   listed with a plain read-only reason, the other ideas keep working, and it recovers when the file is fixed. Test:
   Task 6 `test_broken_toml_idea_is_read_only_and_recovers`.
3. **A run that fails** (a BenchRunError, or an energy-check failure). The Stage shows the failure in words with the
   idea, never an endless "running". Test: Task 7 `test_failed_run_shows_on_stage`.
4. **A run left holding the lock when its process is killed.** The lock is released by the OS, and the page never says
   "the agent is running" forever. Test: Task 3 `test_lock_from_killed_process_is_free`.
5. **The idea on stage deleted or renamed outside.** The Stage moves to the next most recent idea with a notice, no
   error page. Test: Task 6 `test_idea_deleted_outside_leaves_stage`.

### Task 2: Every problem, with its key, and overlap warnings

**Files:**
- Create: `scrimmage/bench/problems.py`

  change

**Interfaces:**
- Produces:
  - `BenchError(message, key: str | None = None)`.
  - `@dataclass(frozen=True) Problem(level: Literal["error", "warning"], key: str | None, message: str)`. `key` is the
    most specific dotted path known (`"bar.kicker.spring"`, else `"bar.kicker"`, else None).
  - `collect_problems(path: Path) -> tuple[Bench | None, list[Problem]]`. First it collects parse errors from every
    entry it can. Only when there are none does it build and add `check_clear` errors, then warnings:
    `bench.warnings` and `overlap_warnings`. Bench is None when there are errors.
  - `overlap_warnings(built: Built, bench: Bench) -> list[Problem]`.
  - `check_file(path) -> tuple[Bench, str]`: unchanged on success. On errors it raises
    `BenchError("\n".join(messages))`, with every error.
  - MCP `bench_check` result gains `"problems": [{level, key, message}]`. On errors it raises `ToolError` with all
    messages.

Collecting mode:
- `parse_bench(raw, base_dir, problems: list[Problem] | None = None)` keeps raising at the first error when
  `problems` is None.
- With a list, it parses each table and entry (bench, piece, each shaft, each list entry, flight, run, sweep) inside
  its own try. Each error is appended and that entry skipped; the cross-checks (a wheel's shaft, CAD slots, couplings)
  run on what parsed. At the end it returns None if any error was appended.
- `_Table` sets `key` from the section, the entry name and the key it was reading.

`overlap_warnings`:
- It considers pairs of geoms of different shapes (`layout.shape_of_geom`) where at least one shape moves: a wheel, a
  springy bar (`spring` set), or a CAD part with slots.
- It warns when `mujoco.mj_geomDistance` (distmax 0.01) is below −0.002 m, once per shape pair.
- Message: `"wheel 'top' and bar 'kicker' overlap by 12 mm"`; key: the first shape's entry key.
- Static shapes touching each other (a hood joined to its flare) are never warned about.

**Files:**

  - `.gitignore` (`.scrimmage-bench/`)

**Interfaces:**
- Produces, all taking `folder: Path`, the session (a bench file's parent folder), state in `folder / ".scrimmage-bench"`:
  - `log_event(folder, kind: Literal["run", "sweep", "compare", "gallery"], files: list[Path], out: Path, source: Literal["cli", "agent", "page"], ok: bool, error: str | None = None) -> None`.
    This appends one JSON line to `log.jsonl`: `{seq, t, kind, files, out, source, ok, error}`, with absolute paths
    and seq counting up from 0.
  - `read_events(folder, since: int = 0) -> list[dict]`: the events with `seq >= since`. A torn last line is ignored.
  - `bump(folder, file: Path, keys: list[str]) -> None` moves `keys` to the front of that file's list.
    `focus(folder, file) -> list[str]` reads it, newest first, at most 12 kept. Stored in `focus.json` as
    `{file name: [keys]}`.
  - `changed_keys(old_raw: dict, new_raw: dict) -> list[str]`: the dotted keys whose values differ (added, removed or
    changed), for every section in `spec._SECTIONS`.
  - `run_lock(folder, holder: dict, wait: Callable[[dict], None] | None = None)`: a context manager holding an
    exclusive OS lock on `run.lock` (`fcntl.flock` on POSIX, `msvcrt.locking` on Windows). It blocks until the lock is
    free, calling `wait(holder_of_other)` once if it has to wait. While held, `holder.json` holds
    `{source, file, pid, since}`.
  - `lock_holder(folder) -> dict | None`: the holder while a live process holds the lock. It tries a non-blocking
    acquire, so a stale `holder.json` reads as None.
- MCP tool: `bench_focus(path: str, keys: list[str]) -> str`. Each key is checked with `spec._check_path` against the
  file. It bumps them and returns `{"ok": true, "focus": [...]}`.
- CLI runs log with source `"cli"` and MCP tools with `"agent"`. While waiting, the CLI prints
  `scrimmage: waiting: <source> is running <file name>` once.

### Task 4: Bench edit operations

**Files:**
- Create: `scrimmage/assembler/bench_edits.py`
- Test: `tests/test_bench_edits.py`

**Interfaces:**
- Consumes: `tomlutil` helpers, `edits.EditError(field, message)`, `spec._check_path`, `spec._resolve_includes`.
- Produces pure functions on a tomlkit document. Each raises `EditError(field, message)`, with field the dotted key
  or `"status"`:
  - `set_value(doc, key: str, value) -> None`. None removes the key; setting `x` drops `x_in` and the other way round,
    as `with_overrides` does.
  - `add_entry(doc, section: str, name: str | None = None, fields: dict | None = None) -> str`. It returns the name
    used (`wheel1`, `wheel2`, ... when None) and fills `DEFAULTS[section]` under `fields`. For a wheel with no shafts
    it also adds `[shaft.<name>]` with `DEFAULTS["shaft"]`.
  - `remove_entry(doc, section: str, name: str) -> None`. It refuses a shaft that wheels or CAD slots use, naming them.
  - `rename_entry(doc, section: str, name: str, new_name: str) -> None`. It also rewrites `wheel.shaft`, CAD
    `slots`, `coupled_to`, `flight.outlet` and `[sweep]` keys that name it.
  - `override_included(doc, raw_merged: dict, section: str, name: str) -> None`. It copies the merged entry into the
    file, so the file's own entry wins.
  - `new_bench_text(name: str, author: str, idea: str, example: Path | None) -> str`. `example=None` gives a blank
    bench (one `2026-fuel` piece, one shaft, two wheels pinching, one inlet, one outlet) that loads.
  - `DEFAULTS: dict[str, dict]`: a minimal valid entry per section.

**Interfaces:**
- `recent.py`:
  - `remember(path: Path, kind: str) -> None` and `recent() -> list[{path, kind, t}]`, newest first, at most 12.
  - Stored in `$SCRIMMAGE_CACHE/recent.json`, else `~/.cache/scrimmage/recent.json`. Missing files are dropped on read.
- `BenchSession(folder: Path, on_change: Callable[[], None])`:
  - Ideas are the folder's `*.toml` files that classify `"bench"`, each a `ConfigDoc`.
  - A background poll every 0.25 s reloads changed or new or deleted files and reads new log events. An outside
    change bumps `changed_keys` into focus and the version.
  - Methods behind the routes: `state()`, `wait_state(since)`, `view(file)`, `idea(file)`, `edit(body)`,
    `history(which, body)`, `new_idea(body)`, `file(path)`.
  - Runs come in Task 7.
- `App` start mode: with `path=None`, robot and scenario routes answer 404 `{"error": "no robot is open"}` and bench
  routes 404 `{"error": "no idea session is open"}`.
- Routes (all JSON, token-protected):

  ```
  GET  /api/app/state            -> {mode: "start"|"robot"|"bench", path, display_path, recent: [...],
                                    examples: [bench example stems]}
  GET  /api/app/browse?dir=D     -> {dir, parent, entries: [{name, path, kind: "folder"|"robot"|"scenario"|"bench"}]}
                                    (D defaults to the working directory; hidden entries left out)
  POST /api/app/open {path}      -> {ok: true}; 400 not a robot, scenario, bench file or folder; 409 while a drive
                                    session, scenario run or bench run is active. The page reloads itself after it.
  POST /api/app/new {kind: "robot"|"scenario"|"session", path, template?, robot?}
                                 -> writes the template (robot: swerve|swerve-rev|differential; scenario: robot
                                    required; session: makes the folder) then opens it; refuses existing paths.
  GET  /api/bench/state[?since=N] -> {version, folder, display_folder, stage: file|null, lock: holder|null,
        ideas: [{file, name, author, idea, read_only_reason, problems: [{level, key, message}], focus: [keys],
                 can_undo, can_redo, latest: {kind, ok, error, t, source, out, headlines, uncalibrated,
                 pictures: {path_side, pass_gif}} | null}]}; long-polls like /api/robot/state.
        stage: the idea most recently edited or run by anyone.
  GET  /api/bench/fields          -> fields_payload()
  GET  /api/bench/view?file=F     -> bench_view of F, or {} while it has errors
  GET  /api/bench/idea?file=F     -> {own: the file's tables as plain values, included: {entry key: source file},
                                      merged: plain merged raw}
  POST /api/bench/edit {file, version, op, ...}: set {key, value}; add {section, name?, fields?};
        remove {section, name}; rename {section, name, new_name}; override {section, name}
        -> {ok: true, version} | 200 {ok: false, errors: [{field, message}]}. Writing rule as the scenario's: a
        candidate is written if it has no more errors than the file now has. A page edit bumps its keys into focus.
  POST /api/bench/undo, /api/bench/redo {file, version}
  POST /api/bench/new_idea {name, author, idea, example?} -> {ok: true, file}; the file is named from name,
        made unique
  GET  /api/bench/file?path=P     -> a file under the session folder or under an `out` the log names; 404 otherwise
  ```

  - `compare.sweep_benches`, `compare.compare_benches`, `gallery.write_gallery`;
  - the App's `SimLock`.
- Routes:

  ```
  POST /api/bench/run {file}                     -> {ok: true, id}; queued behind the session lock (waits; the state's
                                                    lock shows who holds it); 200 {ok: false, errors} when the idea has errors
  POST /api/bench/sweep {file, key, values}      -> {ok: true, id}; key a dotted key, values a non-empty list
  POST /api/bench/compare {files}                -> {ok: true, id}; two or more
  POST /api/bench/gallery {}                     -> {ok: true, id}; writes <folder>/gallery.html
  GET  /api/bench/jobs[?since=N]                 -> {version, jobs: [{id, kind, files, state: queued|running|done|failed,
                                                    error, out}]} newest first, last 10
  ```

  A finished job is logged, so it reaches the ideas' `latest` the same way an agent run does.
- Results go where the CLI puts them (`<stem>-results/`, `<folder>/compare-results/`). A sweep goes to
  `<stem>-sweep/`.
