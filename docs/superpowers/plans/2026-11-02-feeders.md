# Feeders, Spreads and More Balls Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A human player station on a field that the mechanism's blocks start and stop, with seeded spreads, one
outcome per fed piece ("17 of 20 made it in (85%); 1 stuck in the robot; 2 missed"), floor spreads over a grid of
placements, seven more ball presets, every built-in field in Setup, and drive and turn blocks for swerve robots.

**Architecture:** A range file gains `[[station]]` tables (`scrimmage/testrange/station.py`). The model gets parked
ball slots for each station's pool and its optional chute, and a `Feeder` (`scrimmage/testrange/feeder.py`) in the
`RangeRuntime` releases pieces from that pool. A test's `[setup]` (ball, station overrides, seed, floor spread) reaches
the world as new optional `[range]` keys of the in-memory config, so the world is built for that test. The blocks layer
adds feed blocks, conditions and an `Outcomes` tracker (`scrimmage/blocks/feeds.py`) that settles and classifies every
fed piece. It also adds floor spreads (`scrimmage/blocks/spread.py`, kept like sweeps) and a drivetrain controller for
tank and swerve (`scrimmage/blocks/drive.py`). The Test tab's Setup, block editor and run panel show all of it.

**Tech Stack:** Python 3.11+, MuJoCo (the existing ball ledger and contact model), the assembler's stdlib HTTP server
and vanilla JS ES modules, Blockly (vendored), Playwright for browser tests, the MCP server.

**Spec:** `docs/superpowers/specs/2026-11-02-feeders-design.md` (approved 2026-11-02).

## Global Constraints

- Range, robot, part and test file formats change only by adding optional keys and blocks. Existing files load and run
  unchanged.
- The same physics as the whole-robot simulation, with no test-only shortcuts: a fed piece is an ordinary range ball
  placed in play (`Balls.place`).
- Every `[ball.*]` value carries a `# source:` or `# estimate:` comment. Unconfirmed masses and every stiffness stay
  estimates; reports that print UNCALIBRATED keep doing so.
- Plain words in everything a student reads (high-school CAD students); American spellings.
- Windows is first-class: paths via `pathlib`, file replaces via `scrimmage.cad.settings.replace_file`, the Windows CI
  job runs the new non-browser tests.
- Every server or browser test sets `SCRIMMAGE_RECENT` and `SCRIMMAGE_CACHE` to temp paths. The light/dark contrast
  tests (tests/test_test_browser.py's WCAG tests) pass with the new Setup boxes and run-panel marks shown.
- Never `uv run` in the repo (it rebuilds the .venv). Run tests as `.venv/bin/python -m pytest ...`.
- Numbers the spec fixes: interval default 1.0 s; "stuck" means at rest on the robot for 0.5 s; settle up to 3 s
  after the blocks finish; a station with no stock feeds at most 50 pieces a run; floor spreads are a grid of at most
  25 runs, the last 3 kept; hopper preselection by "hopper", "intake" or "indexer" in a body name; the ball picker
  only on the `intake` and `station` fields.

## Planning decisions

- **Station keys** follow the bench's `[[inlet]]` where it fits. A station has `release` (or `release_in`),
  `heading_deg`, `pitch_deg`, `speed`, `interval`, `stock`, `spread_yaw_deg`, `spread_pitch_deg`, `spread_speed`,
  `spread_position` (or `spread_position_in`), `spread_rotation_deg` and `chute = { width, length, slope_deg }`. A
  spread is a **uniform** ± half-range ("varies within them": a piece never leaves a tight chute's limits), unlike the
  inlet's standard deviations.
- **The chute** is a sloped floor plate and two side walls, built with build_elements' existing box helpers (`_slope`,
  `_upright`) as body `element.<station>.chute`. A raised slope can't be made from a whole `[[element]]` (a `ramp` is a
  wedge on the carpet). Its floor's top runs from one ball radius under the release point, down along `heading_deg`.
  `width` defaults to 1.3 ball diameters, so a station without a width fits any ball the Setup picker offers. The side
  walls stand one ball diameter above the floor.
- **Stations feed balls only.** A `[[station]]` in a disc range is refused ("pieces beyond balls" is project 2).
- **Draws are per station and per feed:** `numpy.random.default_rng([seed, k])` for station k, nine uniforms per feed
  in a fixed order (yaw, pitch, speed, dx, dy, dz, rx, ry, rz). So the same seed gives the same feeds whatever the
  timing. The default seed is 1, as the bench's.
- **A feed waits** while another in-play ball's center is within one diameter of the release point, as the bench's
  inlet does. `start_feeding` feeds at once, then every interval. `feed_one` waits out the interval since the last feed
  and finishes when its piece is released. On an empty station it does nothing (the counts show it). If the release
  point stays blocked it times out (WAIT_TIMEOUT).
- **Test settings reach the world** as optional `[range]` keys of the config dict that `world_for` builds: `ball`,
  `station` (name → overrides) and `seed`. A scenario or robot file may use them too. In a test file, `stock = 0`
  means "never runs out" (the cap of 50 applies).
- **The hopper** is `[test] hopper = [...]` beside `hooks`. A piece is in the hopper when its center is inside one of
  those bodies' boxes, the same box `piece_in` uses.
- **The stand-in** is a robot whose `[robot]` has `standin = true` (the template and "Test it" now write it) or whose
  file name ends in `-standin.toml` (what "Test it" has always named it). Its own bodies are the instances of the stock
  Chassis and Drivetrain families (`assembler/library.py` `_GROUPS`). A ball resting only on those is not stuck.
- **At rest on the robot** means the ball's speed relative to the robot is below `balls.AT_REST_SPEED`, where
  `v_rel = v_ball - (v_robot + w_robot x (p_ball - p_robot))`, so a piece wedged on a moving robot still counts.
- **Settling** happens only after the blocks finish. Motors keep their last commands, the stations stop, and the
  settle doesn't count against `time_limit`. Any other ending (a check failed, time limit, tipped over, cancelled)
  classifies the pieces where they are.
- **The headline:** when pieces were tracked, a finished run's outcome is the counts sentence alone. Any other ending
  is `"<ending>; <counts>"`. A seed that differs from the newest kept run's adds `"; a new shuffle (seed N)"`.
- **Floor spreads** keep the robot at its start. The approach angle turns its heading, and the ball goes `distance`
  ahead along the turned heading and `offset` to its left (+) or right (−). The ball moved is the floor ball nearest
  ahead of the start (within 30° of the heading and 3 m). An axis left out keeps that ball's own offset or distance,
  or 0° for the angle and rotation. Spreads are kept as `spread-<NNN>/` (newest 3), apart from sweeps.
- **Every built-in field gets a start**: `terrain-library` gains `[start.approach]`. Setup puts the robot at a field's
  first start (file order). A new **Start** picker appears when a field has more than one. The station field has
  `at_station` (bumpers against the chute) first and `facing_ball` for floor spreads.
- **"Test it"** puts a stand-in whose part has a hopper-like body (and no hook body) on the station field.
- **Adding the station blocks** to an existing test: Setup shows **Add the station blocks** when the field has a
  station and the test has no feed block. It appends the starter feed blocks and deletes nothing.

## Review Focus

1. A ball picked in Setup that doesn't fit (a 25 in 2014 ball in a chute with a set width, or overlapping the
   field's floor balls): one plain problem in Setup, Run refused, nothing crashes, and picking FUEL again clears it.
   Test in Task 6.
2. A piece that stops at the release point (the chute's low end jammed): the station waits, `feed_one` times out
   naming the station, and the counts still add up to the feeds. Test in Task 7.
3. A run that ends early with pieces in the air (time limit, tipped over, cancelled): every fed piece still gets exactly
   one outcome, the counts add up, and the moving ones are "still moving when the run ended". Test in Task 7.
4. A hand-edited `[setup]` with an unknown key or a bad value (`seed = 2.5`, `station = { nope = {...} }`, a
   36-placement floor spread): one plain error naming the key. Test files written before this project (no `[setup]`,
   no `hopper`) load, round-trip and run unchanged. Test in Task 5.
5. A sweep of the seed or of a station setting with a value that can't run (`2.5` for the seed, `-1` for an interval,
   a station the field doesn't have): a row with a plain message for a bad value, a refusal before any run for a bad
   station. Test in Task 8.
